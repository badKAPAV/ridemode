# M2-NAV — In-app Google Maps widget

Status: IN_PROGRESS (2026-11-20). The widget, SDK integration and isolated state machine are implemented and compile; real-device acceptance is pending. Keys remain only in the ignored root `.env`.

## Scope and contract

- Requirement: M2-NAV-001; minimum 4×4 cells, with responsive compact and temporary full-grid presentations. A Grid button appears beside End Ride only while expanded. Expansion hides other widgets visually and preserves every saved rectangle and the current page. Tapping the map or Search expands; the expanded map supports normal browse gestures.
- Idle: show a location-centered Navigation SDK map without a destination. If location is unavailable, show a map and explicit location action/state; do not pretend the rider's position is known. A recenter control returns from free browsing to the current location. After a real-device false-unavailable report, recenter uses a recent cached fix and bounded fused/network/GPS one-shot fallback; if only a recent fix remains, label it as recent.
- Search: bottom-right Search opens the expanded search UI. Programmatic Places Autocomplete (New) begins at three entered characters and after 1,000 ms without an edit. Cancel pending debounce, cancel/ignore obsolete responses, and do not issue duplicate queries. Restrict predictions to India with `setCountries("IN")`; `setRegionCode("IN")` alone is not a country restriction. Use a fresh session token per search, a location bias when useful, and only minimal Place Details fields needed to obtain/display the destination. Handle empty/no-network/quota/error states and required Google attribution.
- Selected: show only the start point (`Your location`) and the selected end point, plus Start navigation. Do not show ETA, route line, distance, route alternatives or a route preview. Place selection/Details may itself use a billable Places request; no Navigation SDK route request happens here.
- Start: only an explicit tap on Start navigation calls the Navigation SDK route-setting method. Disable duplicate starts while in flight. On a successful route, start guidance and show the live map/directions, remaining time, distance and arrival time; keep the SDK ETA card hidden in favor of one custom progress card. On route error, keep the destination and offer a deliberate retry; do not silently issue repeated billable route requests.
- Grid: during search or selected destination, discard the draft and return to the compact idle centered map. During route-starting or active navigation, collapse the visual map to its saved widget size and keep the one navigation session and its request alive. Compact active guidance hides the SDK header, uses a smaller progress card/end control, and restores the follow camera after resize. Re-expanding restores the same session and route.
- Arrival/end: use final-destination arrival event to stop guidance, clear destination, release listeners/notifications as required and return to idle map. End Ride must also clean up guidance. Distinguish navigation arrival from user cancellation; handle process death/rotation/PiP safely. Avoid a second map/navigation engine when changing size.
- Power and permissions: idle map/location observation runs only while Ride is visible; navigation follows SDK foreground/background requirements and stops explicitly. Review precise-location and background-location grants, foreground service and notification behavior before manifest changes. Respect denied/approximate location, offline map availability, data usage and billing limits.
- Isolation: this widget owns its own map, search, route and navigation state. The existing Turn guidance widget retains its current Google Maps notification source, UI and behavior. Calls, Notifications, Music, Weather, Volume, SOS and all other widgets retain their logic and content. None subscribe to or depend on this widget's state. Expansion only hides them visually; it does not mutate their saved placement or data. The existing Maps shortcut is a separate widget and remains unchanged by M2-NAV.

## Dependencies and acceptance

Needs restricted Android API keys, Navigation SDK and Places API (New) enabled in a billed Google Cloud project, separate dev/release Android app restrictions and quota alerts. The ignored root `.env` supplies `NAVIGATION_API_KEY` and `PLACES_API_KEY` to the build; never commit secrets. Navigation SDK 6.3.3 and Places SDK 4.3.1 use the approved Kotlin 2.1.21 compiler update (ADR-065); the standalone Maps artifact is excluded to avoid duplicate classes. The implementation requests precise foreground location at use; the SDK merges background location in the manifest without an in-app runtime request. It keeps one NavigationView across compact/expanded size changes and cleans up its Navigator on End Ride. Device acceptance still needs the corrected idle recenter and search/route/arrival/collapse/offline/PiP/lifecycle/permission/battery checks. The user reported a real-device false-unavailable location state. The corrected lookup and label compile, lint and package; user device recheck is pending.

## Source notes checked 2026-11-19

- [Navigation SDK overview](https://developers.google.com/maps/documentation/navigation/android-sdk/overview): Navigation SDK supplies both map and guidance, replacing Maps SDK in the app.
- [Navigation SDK billing](https://developers.google.com/maps/documentation/navigation/android-sdk/pricing): successful server route calculations, including no-route responses, can be billed; map and search costs are separate.
- [Places Autocomplete (New)](https://developers.google.com/maps/documentation/places/android-sdk/place-autocomplete): programmatic search, country restriction, region-code distinction, session tokens and selected-place lookup.
- [Navigation events](https://developers.google.com/maps/documentation/navigation/android-sdk/events) and [Navigator reference](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/Navigator): arrival and explicit stop/clear/listener cleanup.
- [Background location practices](https://developers.google.com/maps/documentation/navigation/android-sdk/background-location-usage) and [NavigationView lifecycle](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/NavigationView): Android permission and lifecycle risks.
- [NavigationView ETA control](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/NavigationView): the SDK exposes `setEtaCardEnabled(false)` for hiding its ETA card.

## Current UI refinement — 2026-11-20 (ADR-051)

- Bottom-attached single-line navigation footer at compact (including 4–8 columns) and full-grid sizes, with square lower corners, highlighted time, supporting distance/arrival and matching-height End action. Reserve native map padding for the footer.
- Connected Material 3 Expressive Recenter/Search capsule with Bold icons; animate map position/size over 280 ms, and destination-field width/map visibility over 180 ms. Reduce motion bypasses transitions.
- Opaque full-grid search with read-only From: Current location beside To. Only To expands with keyboard focus; selection or explicit Back restores the pair; keyboard dismissal preserves the query/results. To accepts India Places search or Choose from map with a center pin and explicit confirmation. Pin destinations show coordinates without reverse geocoding.
- Review ride confirmation shows From → To and icon-led Start ride. No arbitrary origins or intermediate stops; no pre-start route request.
- Acceptance still open: user device checks at 4×4, 6×4, 8-column and full-grid sizes; active resize/follow; keyboard selection/back/dismiss; pin selection/cancel; Start-only routing; End/arrival/offline/permission/PiP; font scaling, attribution and Reduce motion.

## Search keyboard correction — 2026-11-20 (ADR-052)

The user reported that the keyboard obscures the destination field/results. Search now uses a full-window Compose Dialog outside the square-cell grid and Ride rail, with one safeDrawing inset owner for IME/bars/cutouts. Predictions precede Choose from map in the scrollable results area. The same map stays mounted underneath; From remains fixed Current location. The saver timer pauses while modal search is open. Device keyboard show/type/results/select/back/dismiss and map-pin round-trip checks remain open.

Keyboard-dismissal correction (2026-11-20): removed the IME-visibility listener that cleared the active field when the keyboard hid. Only explicit Back or location selection closes the active search field; hiding the keyboard keeps the query and results selectable. Device recheck remains open.
