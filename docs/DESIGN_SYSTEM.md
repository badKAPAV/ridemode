# Design system contract

M1 implements `RideTheme`, `RideTypography`, `RideUiTokens`, shared controls and a saved-widget renderer. [Proposed tokens](../config/design-tokens.json) remain illustrative; Kotlin Compose tokens are canonical until JSON-to-Kotlin generation/parity validation exists (ADR-001). PRD constraints take precedence over proposed values.

- Theme: `MaterialExpressiveTheme` from Material 3 `1.5.0-alpha18`; wallpaper dynamic light/dark colors on API 31+, Expressive light/dark defaults on API 24–30. The proposed normal JSON palette does not drive runtime colors. Saver uses true black.
- System bars: `MainActivity` follows the system light/dark setting for status and navigation bar icon contrast. Pixel 8a light-palette screenshot verified dark status icons against the pale dynamic background; physical dark-palette verification remains pending.
- Font and icons: bundled Roboto Flex title/clock uses the user's Google Fonts specimen axes: `wdth 151`, `wght 648`, `GRAD 150`, `XOPQ 96`, `XTRA 603`, `YOPQ 79`, `YTAS 677`, `YTDE -217`, `YTFI 738`, `YTUC 712`, `YTLC 514`, `slnt 0`; optical sizing is automatic. Adjacent page names use the same wide axes with `wght 300`/`GRAD 0`. API 24–25 uses the bundled font without variation axes. Body and labels use the same Roboto Flex axis set at weight 400 and grade 0. In-app UI icons use Phosphor `Fill` vectors except the X and Plus buttons, which use normal `Regular` strokes; the Android notification small icon remains a filled monochrome vector. OFL licenses are in `docs/licenses/ROBOTO_FLEX_OFL.txt` and `docs/licenses/PLUS_JAKARTA_SANS_OFL.txt`.
- Shared controls: `RideActionButton` has 64 dp minimum height; `RideSurface` uses expressive theme surfaces; `RideLoadingIndicator` uses Material 3's morphing shape loader and an accessibility label. These are foundation components, not registered dashboard widget types.

- Typography: PRD target is clock 64–120 sp by widget size, primary labels 20–28 sp and secondary 14–18 sp with font scaling. Current compact widget cards use Material typography and do not yet meet every size target; saver clock uses 96 sp.
- Color: high-contrast dark ride UI, true `#000000` OLED idle, restrained accent and color-independent priority markers. Keep navigation freshness visible.
- Spacing: Ride/editor canvases use 40 dp side insets, 16 dp vertical insets, 12 dp rail gaps and an 8 dp gap between distinct widgets; editor grid uses at least 12 columns and 6 rows with 52/60/68 dp preferred square-cell choices. Pixel 8a uses a six-row 52 dp baseline; larger screens keep cells at least that size, while smaller screens scale down to retain the minimum counts. The viewport determines any additional whole rows and columns; odd counts are valid. Editor and Ride draw equal-width/equal-height cells in a top-aligned, horizontally centered grid, leaving only the remainder of less than one cell outside it. Ride fits saved cells into its actual viewport without vertical scrolling; even a page with one visible widget retains its saved grid rectangle in Ride/preview. The editor shows a dotted grid. The rail has a 13 dp rounded rectangle corner, with page title/status only at the bottom.
- Touch: editor resize points have 28 dp gesture areas around 12 dp visible dots, centered on the rounded selection border; editor and Ride rail buttons have 56 dp minimum height. This meets the minimum target but is below the 64–80 dp target for primary ride controls; glove and accessibility checks remain.
- Accessibility: TalkBack labels/actions, font scaling, contrast checks, reduced motion option, solid numeral fallback when outline loses readability. Test sunlight, gloves and vibration while stationary.
- Landscape: Home/Settings remain system-oriented; the editor locks landscape and Start Ride opens a dedicated sensor-landscape activity with saved enabled pages. Its canvas never scrolls, while horizontal paging remains. A rounded tonal surface sits behind the editor and Ride bottom rails. The compact Ride rail shows an outlined X + two-line End/ride label, previous/current/next page names at 0.34/0.78/0.34 opacity, disabled normal MapPin + Open and a secondary-color icon-only microphone assistant preview. Adjacent names keep the wide font with thin weight. The page indicator slides 220 ms in the swipe direction or changes immediately with reduced motion. PiP uses a centered status. Android may keep system bars visible for an active call; no-call immersive and safe-inset checks remain.
Fresh Ride startup (ADR-060) uses titleLarge RIDE with a fixed-width HARD/SAFE slot, fade-out then fade-in, and bottom-centered one-line helmet text with a filled Warning icon. The opaque screen then slides up to reveal the dashboard. Nominal sequence: 800 ms HARD hold, 100 ms fade-out, 140 ms SAFE fade-in, 1000 ms SAFE hold, 360 ms upward reveal (2400 ms total; cubic easing 0.2,0,0,1). Measured word width prevents movement of RIDE; measured advice width preserves a single line within safe insets. Pointer input stays blocked until completion. Existing Settings/Reduce motion/active-session/lifecycle/PiP rules remain unchanged; device review pending.

- Editor: page management uses a bottom sheet with direct add/open/rename/delete controls and hold-to-drag ordering; Move earlier/later remains as a non-drag fallback. Add widget opens a scrollable bottom sheet over 12 dp blurred editor content. Dragging is clamped to the grid; a move into one occupied widget relocates that widget when a valid cell exists. Resize overlaps and moves into multiple widgets are rejected. Selected widgets show eight resize points and a rounded selection border; widget options sit in the bottom editor rail and offer Rotate only when the swapped size is valid and an empty page placement exists. Overflowed or legacy undersized saved widgets can use Fit to grid; unsafe resize handles stay hidden until the placement is valid. Preview hides editing controls.
- OLED: a black overlay displays the persisted Classic (default) or Row style at the selected 15/30/60/120/300-second idle delay. It fades in and out over 350 ms, immediately with Reduce motion, while consuming the wake touch. Classic keeps one centered column: outlined or solid clock, live/cached weather, live session song/artist or explicit access/empty state, local battery percentage without icon and half-opacity wake hint. Row places very large, tightly stacked hours/minutes and body-style date at left; the clock uses the Outline clock switch and the Roboto Flex maximum grade 150 with weight 1000. Three rounded black panels with 1 dp white strokes and 20 dp gaps sit at right. Content is centered horizontally and vertically with no category labels: music icon and current session state, weather icon and live/cached condition or the error state, local battery percent with a normal or charging icon. All Row elements, including its wake hint, use black or white only; the battery panel shows Unavailable when the OS level cannot be read. Live weather is implemented in M2 pending device acceptance. The app changes only its own window brightness when enabled; pause restores brightness. Pixel 8a previously verified the 15-second timeout and consumed first touch; this revision awaits user visual check.

Calls now uses a secondary tonal container with one vertical child scroll for five system Recents. Calls and Notifications have 4×5 minimum, 6×5 default and full 12-column/device-row maximum; old undersized placements show a resize prompt. Each row shows initials, contact name when cached, number, call type/time and a direct-call icon only for callable numbers; confirmation and permission precede ACTION_CALL. Notifications uses a tertiary container with one vertical child scroll for ten active entries, messages first. Each row shows avatar or initials, sender/title, body limited to two lines with ellipsis and available localized posting date/time in a quieter label that may wrap to two lines. Empty, access-needed and unavailable states are explicit. The persisted Privacy mode switch replaces notification rows with a hidden-content message in Ride and editor. Turn guidance uses a primary tonal card, prominent direction glyph, source instruction, available route details and compact/expanded layouts. Its access, idle and stale states are explicit. Assistant retains a mock/unavailable card. Shared Kotlin spacing and shape tokens govern the widgets. Speedometer and SOS now have per-instance settings; other settings remain proposed.

The M2 Google Maps widget: minimum 4×4 square cells, outlined idle location label and Bold Phosphor Recenter/Search icons in connected Material 3 Expressive leading/trailing controls. A 280 ms transform moves/resizes the same map between its saved rectangle and full grid; Reduce motion is immediate. Search uses an opaque full-window modal surface above the Ride rail with the map retained behind it. This window consumes safeDrawing/keyboard insets once, keeping the field above independently scrollable predictions; Choose from map follows predictions. From is a non-editable Current location field beside To; To expands over 180 ms, requests keyboard focus, and returns to the pair only after selection or explicit Back. Keyboard dismissal leaves the expanded search field, query and selectable results intact. Destination search uses rounded filled input and icon-led surfaced results, preserving Google attribution; Choose from map returns to the live map with a center pin and an explicit Use this location action. Review ride opens a clear From → To confirmation and icon-led Start ride action, without estimates or route preview. During navigation, one full-width single-line footer attaches flush to the viewport bottom: rounded top and bottom corners, prominent tonal time label, supporting distance/arrival and a 56 dp End/X action matching its height. SDK map padding reserves footer space. Expanded navigation retains the SDK turn header; compact navigation hides it and restores follow camera after resizing. Grid discards an unstarted draft; active/start-in-flight routes survive collapse. Other widgets retain saved state and placements. Device visual, keyboard, attribution and interaction acceptance remains pending.

Clock is now a rounded surface widget with three lines from top: responsive bold wide Roboto Flex local time, then smaller wide Roboto Flex day/date and live/cached weather text at weight 300/grade 0, alongside a Phosphor condition icon and temperature. The whole three-line group and each line are centered, including the combined icon/weather row. The surface encloses all three lines. Its 2×1 minimum omits weather below three rows; wide one-row cards place time and date beside each other using larger fitting text, and narrow ones stack the two. At three rows and above all three lines remain available; default is 4×3 and full 12-column/device-row height is allowed. Weather is no longer a separate addable widget. Saved Weather placements become Clock instances in place, so an existing page with both can show two combined tiles until edited. Live weather data is wired in M2 pending device acceptance.

Battery uses a filled dynamic-primary level segment and a subdued remaining segment with a narrow transparent seam, following the supplied rounded split reference. The bold percentage appears at start/bottom and the plugged-in power icon at end/top, without a This phone label. They fit independently into filled/empty regions, account for icon space and use per-region contrast; the percentage can reclaim a larger part of the bar. One shared logical-axis geometry is drawn horizontally or vertically, so empty/full bars also retain their content and rounded corners. Battery uses 2×N or N×2 cells, with N≥4; it defaults to 4×2 and grows to the device boundary while retaining the two-cell axis. The Maps shortcut is a filled rounded primary tile with a filled navigation arrow, wide bold `Open Maps` and a small Mock label; M1 does not launch Maps. SOS favorites are individual rounded primary square tiles with images when supplied and initials otherwise; up to six fit in a width-and-height-aware row/column grid and are spaced evenly. SOS now renders only real saved snapshots or an empty setup prompt; editor previews never dial. These three widgets bypass the generic outer card.

Implemented screens: Home has a primary-container Ride hero and compact navigation cards linking to Settings, Getting Started, Access and Privacy, and the Page Editor. Home and secondary screens use 16 dp horizontal/12 dp vertical content insets and 12 dp section gaps. Tonal cards use 12 dp inner padding, 10 dp icon/text gap and 40 dp icon containers. The Back control keeps a 56 dp hit area but draws a 40 dp tonal circle with a 20 dp icon after an 8 dp leading inset. Home and secondary screens place the page title in a Material 3 top app bar; secondary titles sit beside a filled tonal Back icon button. Supporting text stays in scrollable content. Tonal feature rows use distinct Phosphor icons and alternating primary/secondary/tertiary icon containers. Settings groups switches and uses connected expressive toggle buttons for one selected idle delay. Getting Started relies on the app bar Back control; no redundant Return home button remains. Home starts Ride. Settings has keep-awake, OLED and reduced editor motion controls; later incoming-message controls are explained only. `RideScreen` supplies the top app bar, portrait scrolling/insets and Back control. Six templates are editable and persisted; most widget cards still use labeled mock data for later integrations. Assistant visual states are simulated; execution remains M3. Music has a dedicated responsive column without a generic outer card; its metadata lines use a bounded central group with a 4 dp gap, so large cards do not spread the title and artist apart. Its top half is one full-width rounded low-opacity primary song-details background, with a separate rounded square cover-art tile over the left edge and song/artist text inset to the right. Three equal-width controls fill the remaining height. The center Material button stays filled and changes icon with live playback state; its corner radius animates over 220 ms from a paused capsule to a playing 13 dp rounded rectangle. Previous/next remain transparent at rest. Music starts at 5×4, permits square sizes and sizes through 12×12, and requires width≥height. Metadata can grow to 28/22 sp when room allows. Editor preview crossfades over 150 ms or changes immediately with reduced motion enabled. Volume now has no generic outer card. Its two detached segments occupy a 1×N vertical or N×1 horizontal grid rectangle: a translucent dynamic-primary empty segment and a solid-primary fill, with flat inner ends, rounded outer ends and a line across the transparent gap. The live system percentage uses the wide bold Roboto Flex title style at the top/start in whichever segment fits and transitions between them. Fill and counter movement animate over 160 and 180 ms. The long axis is bounded by device rows or 12 columns. A shared measured text component wraps within each widget, scales line height with text size and prefers at least 14 sp; Battery percentage keeps a larger floor. Emergency shrink is used only when the text still cannot fit. TalkBack, broader contrast and font-scale checks remain open.

Implementation references: [Material 3 Expressive theme](https://developer.android.com/reference/kotlin/androidx/compose/material3/MaterialExpressiveTheme.composable), [Material 3 releases](https://developer.android.com/jetpack/androidx/releases/compose-material3), [Compose variable fonts](https://developer.android.com/develop/ui/compose/text/fonts), [Roboto Flex source](https://github.com/google/fonts/tree/main/ofl/robotoflex), [Plus Jakarta Sans source](https://github.com/google/fonts/tree/main/ofl/plusjakartasans), [Phosphor Compose port](https://github.com/adamglin0/compose-phosphor-icon).

The volume bar keeps its detached dynamic-primary segment geometry in Ride and editor. Ride tap/drag and accessibility progress set actual music-stream volume; the editor canvas is read-only. The percentage comes from Android’s current bounded stream level, and unavailable volume shows an em dash. Route, Bluetooth and large-text appearance require device review.

Live weather in Clock and both OLED saver styles uses the condition icon and temperature when a usable reading exists. A cached reading older than 45 minutes carries an age label. Loading uses `Checking weather`. Missing/expired/unrecognized weather uses the filled CloudLightning icon and exact text `Something's not right`; no fabricated weather value appears. Narrow Clock weather text can wrap within its cell.

Ongoing Maps controls (2026-11-20, ADR-053): retain the usual rounded outer shape in every state, with a rounded progress footer. Expanded guidance adds an icon-led voice dropdown with Mute/All/Alerts only and the selected mode; compact views omit it. End replaces the map with a centered whole-widget confirmation and Keep/End actions plus a five-second countdown. Guidance continues underneath; timeout/Back/Keep returns to the map. Ending/retry states explicitly cover the map; idle rendering returns only after successful SDK teardown. The saver timer pauses during confirmation/ending.

Ride quality-of-life (2026-11-20, ADR-054): while the pager moves, Maps shows a Material 3 Expressive CircularWavyProgressIndicator on its normal widget surface; first native initialization waits for a settled page, and an existing view is hidden rather than destroyed during movement. End Ride uses a full-screen surfaced confirmation with Keep riding/End ride actions, five-second countdown and 56 dp minimum button height. Page names are transparent TextButtons spanning their allocated rail width with 56 dp minimum height, retaining current/adjacent type hierarchy and ellipsis. Settings includes Show Maps shortcut; its default preserves the existing toolbar presence. Access and Privacy uses short icon-led cards, descriptive Android Settings actions and one concise privacy note; cards cover implemented access rather than future permissions. Device acceptance remains pending.

### Speedometer and SOS — 2026-11-20

Speedometer uses the existing surfaced large shape and measured number fitting, 4 dp inset, 144 sp number cap and horizontal layout above 2:1 width/height. 1×1 retains speed/dash plus unit; larger tiles add status if enabled. Tall and wide rectangles have no aspect restriction. Status is always exposed through semantics, including small tiles. Editor shows Preview rather than live GPS. Tap requests precise location or opens location/app settings when needed.

Speed/SOS Widget settings use a full-window safe-inset dialog with persistent draft, Save/Cancel, scrollable content and IO busy/error states. Connected expressive buttons choose units. SOS tiles use selected photos or initials with a high-contrast bottom name strip (surface opacity 0.9), existing tile sizing and vertical scrolling for additional rows. Widget editing supports contact name/number/photo/reordering/removal and explicitly describes per-instance ownership. Calling requires a name-and-number confirmation.

Ride action confirmations (2026-11-20, ADR-059): shared RideConfirmation content replaces small call AlertDialog actions and separate Ride/navigation countdown labels. Window-sized call dialogs cap at 720 dp; End Ride stays full-screen and navigation stop stays within the widget. At ≥420 dp content width, actions are 96 dp high with horizontal icon/bold titleMedium text; narrower views use 80 dp actions with stacked icons/text. Calls use primary/onPrimary; destructive end uses error/onError. Dismiss/Keep uses a visibly tinted secondary-container fill over surfaceContainerLow, continuously draining from full to empty against the actual five-second monotonic deadline (RTL mirrored), integer seconds and accessibility state description. Progress is time information and does not rely on animation-duration settings. Parent surfaces clip fills to the existing large shape. Compact title/detail are capped at two lines. Device/font-scale/glove acceptance is pending.

Intro warning stability (2026-11-20, ADR-062): reserve system-bar space independently of bar visibility, unioned with display-cutout insets, instead of live safeDrawing padding. Give the warning text an explicit measured/fitted width so the icon/text row keeps the same center through word changes and reveal. Bar space stays reserved while hidden. Existing local 70 sp title override is preserved. Reported on-device glitch needs device confirmation; see [Compose inset types](https://developer.android.com/reference/kotlin/androidx/compose/foundation/layout/package-summary).

Map lifecycle recovery (ADR-063): theme/palette recreation retains route state while native views can be replaced. A Java native-map failure triggers one automatic view reload, then an explicit Map display unavailable / Reload map surface. End navigation remains available during active guidance if the display fails. View recovery does not silently end or request a route. Existing map size, deferred-loading and reduced-motion contracts are unchanged; SDK deadlock/device acceptance remains open.

Palette refresh explicitly observes LocalConfiguration in RideTheme, with colors cached per context/configuration/dark mode. Color changes refresh the existing theme while controller identity remains independent of palette values. Native view recreation still follows the actual Activity lifecycle.

Turn guidance/assistant refresh (2026-11-20, ADR-066): use surfaceContainerHigh and onSurface text, with primary-tinted Phosphor Bold maneuvers up to 224 dp. Adaptive core layout switches between wide side-by-side and tall/square stacked regions; distance 24–80 sp, instruction 18–42 sp, details 14–24 sp. Empty state shows a large navigation icon and “Where do you wanna go?” only. Current state shows notification values, deduplicated supporting text and no app category/experimental badges. Guidance uses AdaptiveWidgetText's new opt-in hard minimum plus ellipsis; all existing callers retain their previous shrink/clip defaults. Explicit tap invokes existing RideConfirmationDialog styles and five-second dismiss fill before strict Maps launch. Assistant tile uses the same dark surface/microphone and opens the device assistant; rail microphone stays visibly disabled. Saved Maps shortcut tiles remain renderable but are absent from the add menu. New guidance bounds are 4×4 min, 7×4 default, 7-column/device-height max. Device/font-scale review pending.

Widget alignment refinement (2026-11-20, ADR-067): Assistant centers the icon/text group in both compact row and taller column layouts; the exact Open Assistant label wraps to a maximum of two lines with measured fitting. Guidance reserves the final full-width centered titleMedium/bold line for real arrival time, below supporting details. Music artwork and song details use their existing separate rounded surfaces as app-open targets; retain current transport layout and shared large timed confirmation buttons/dismiss fill. No new visual token values. Device sizing/font-scale acceptance pending.
