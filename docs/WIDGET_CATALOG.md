# Widget catalog

[JSON catalog](../config/widget-catalog.json) proposes stable IDs, dimensions and settings; `WidgetRegistry` implements all 12 active IDs and min/default/max sizes, checked against JSON by `scripts/verify-docs.py` (ADR-001). Dimensions below are columns × rows on a device-wide square grid with at least 12 columns and 6 rows; additional whole columns and rows fill the viewport and odd counts are allowed. Pixel 8a targets about 52 dp square cells; larger screens use at least that side, smaller screens scale down to keep the minimum grid. Overflowed saved widgets are fitted when a valid free placement exists; otherwise their records remain for manual Fit to grid. Catalog width 2147483647 means device-width maximum, clamped to actual columns, for Volume, Calls and Notifications. Other widget maxima stay as listed; height maxima are clamped to available rows. In the editor, Rotate appears only when swapping a widget’s width and height remains valid and an empty placement exists. `WidgetCard` renders every type in editor and Ride; Unimplemented M2/M3 content defaults to explicit Mock/Unavailable states; `WidgetCard` accepts optional typed content for later per-instance adapters. Registry validation rejects unknown IDs and invalid sizes before Room writes. New widgets are placed at their smallest valid registered size when space allows. Speedometer and SOS settings now have per-instance editor controls; other JSON settings remain proposed. Normal/OLED visual and accessibility checks remain open.

Widget icons use Phosphor `Fill` by default, with Bold guidance/Maps actions and existing Regular X/Plus exceptions; Turn guidance uses oversized Phosphor Bold maneuver vectors derived from explicit notification text. Clock uses local time and live or cached weather with an explicit failure state; battery reads local capacity. Separate Weather is no longer addable. Existing Weather placements convert in place to Clock; a page may then have two combined Clock tiles until the user removes one. Shared measured text wraps and scales within the actual rendered bounds, with a 14 sp preferred floor and a smaller emergency fit only when needed. Assistant now delegates to the device default assistant; local M3 command recognition remains planned. Calls/Notifications and Turn guidance use current native sources and need device acceptance. Ride and editor preview use the saved widget rectangles even for a page with one visible widget. OLED idle offers the default single-column Classic style and a Row style with larger stacked clock/date at left and centered live song state, live/cached weather and local battery/charging content inside widely spaced 1 dp white-outline black panels at right; the song and weather have white icons. Both keep a wake hint. Music now uses a live session source after the Android access grant; real SOS picker/photo/edit behavior is implemented pending device acceptance; weather needs device acceptance. Remaining M1 work is user device acceptance of the preview visuals. Speedometer/SOS settings have runtime codecs; other JSON settings keys remain proposed. M1 tests must never interpret mock data as live native integration. See [PRD](PRD.md), [design](DESIGN_SYSTEM.md) and [capabilities](ANDROID_CAPABILITIES.md).

The new `google_maps` widget is isolated from `maps_shortcut` and notification-derived Turn guidance. Other widgets retain their data and saved placements while visually hidden by map expansion. Its live map and route lifecycle still require real-device acceptance; the editor preview is intentionally static.

Maps UI refinement (2026-11-20, ADR-051): `google_maps` keeps the 4×4 minimum. Idle actions are a connected Bold-icon capsule; full-grid search fixes From to Current location and edits only To via Places or a center map pin. Review ride precedes Start ride. Navigation progress and End share a bottom-attached single-line footer at every size. Grid/search transitions honor Reduce motion; saved geometry and other widget sources are unchanged. Device acceptance remains IN_PROGRESS.

Keyboard correction (2026-11-20, ADR-052): `google_maps` search now covers the full window and Ride rail, with one keyboard/system-bar inset owner outside square-cell sizing. The destination field remains above scrollable predictions; map-pin selection remains available after predictions. Device acceptance is pending.

Navigation lifecycle controls (2026-11-20, ADR-053): google_maps keeps rounded lower corners during guidance, shows the voice menu only when expanded, and confirms End over the full widget with a five-second cancel deadline. Arrival/end restores the centered idle map after SDK teardown; cleanup errors retain Retry end. Catalog sizes and editor preview stay unchanged. Native notification/audio/GPS/camera/timer acceptance remains pending.

Maps paging refinement (2026-11-20, ADR-054): google_maps shows an Expressive circular wavy indicator until its page settles and the native map is ready. An already composed map view is hidden during pager motion and restored without recreation; the Activity controller retains route state. Size/placement/editor-preview contracts are unchanged. Performance and active-route paging need device acceptance.

Speedometer (`speedometer`, ADR-057): 1×1 min, 3×3 default, both maxima 2147483647 meaning the actual device grid boundary. Any rectangle/orientation is valid; add/resize/rotate reuse registry/editor controls. Settings: units (`default`, `kmh`, `mph`), showStatus (true). Global Settings → Speedometer supplies inherited units. Existing saved pages are never seeded with an unwanted speed tile; add it in the editor. Live foreground GPS only; no fix/stale/error shows a dash.

SOS (`sos_contacts`, ADR-058) keeps 2×2 min/6×3 default/12×6 max. Widget options → Widget settings selects up to six phone rows and edits names, number selection, photo/initials, order/removal, and directCall (false default). Each widget on each page owns contacts independently; copied widgets initially copy values and then diverge. Thumbnails are bounded private snapshots; reselect to refresh contact changes. Confirmation precedes dialer/direct call, emergencies always dialer. All saved favorites remain reachable by scroll. No READ_CONTACTS grant is requested. Native integration is implemented; device acceptance remains pending.

Confirmation controls (2026-11-20, ADR-059): SOS and Calls use a large five-second call/dismiss dialog. Google Maps stop retains widget coverage with the same bold icon-led 80/96 dp actions; Keep contains the draining countdown fill. The End Ride surface uses matching controls across the full screen. Widget sizes/settings/registered IDs and calling policy are unchanged. Device acceptance pending.

Google Maps lifecycle (ADR-063): per-widget state lives in a retained Ride navigation ViewModel through palette/configuration recreation. Stop/arrival restores idle after stopping/clearing guidance; final SDK cleanup waits until actual Ride end. SDK singleton route leases allow one widget to navigate at a time, with an explicit message for a competing start. Native view/handle recovery preserves guidance and offers Reload map after one failed automatic rebuild. No registry/size/settings changes. The old 6.1.0 deadlocks motivated the approved ADR-065 SDK update; device route stress validation remains pending.

Picker visibility is distinct from registration: all 12 types remain recognized, but maps_shortcut has availableInPicker=false and is omitted by WidgetRegistry.pickerWidgets. Saved layouts keep legacy tiles. Guidance max-height sentinel 2147483647 means the actual available grid rows; narrower than four columns or fewer than four rows is invalid. Old out-of-contract shapes use the existing resize/Fit flow. ADR-066.

Alignment/source handoff refinement (2026-11-20, ADR-067): Assistant always includes centered “Open Assistant”, up to two wrapping lines, with a compact row or centered column. Turn guidance pins actual notification arrival time bottom-center and omits it when absent; every live tile tap still asks before Maps. Music artwork and metadata container independently ask before opening the tapped provider app, preferring its session activity then package launcher. Five-second dismissal/Back/expiry cancels; transport buttons stay independent, editor inert, missing source disabled and failed launch shows feedback. Registry bounds/config keys remain unchanged.

Music metadata refinement (2026-11-20, ADR-069): Song and artist use size-based typography (line-height constrained, capped at 28/22 sp) independent of string length. While playing, each overflowing line uses an infinite marquee with 1000 ms initial and repeat holds, a 12 dp width-clamped alpha fade at both edges and internal fade padding so resting endpoint glyphs remain readable. Short strings stay static without fades; replacing metadata restarts the hold. This supersedes shared wrapping/length-fitting for these two Music widget lines only. Device motion/size/font-scale acceptance remains open.

Playback clarification (2026-11-20): Both Music metadata marquees stop and return to their origin while paused. Resuming playback begins the one-second initial hold again. Font sizing and overflow fades remain unchanged.

Confirmation presentation refinement (2026-11-20, ADR-071): SOS/Calls, Music source handoff and Turn guidance handoff show container-free content over a dimmed screen. Google Maps End shows the same content over its dimmed visible map, with guidance continuing. Shared 80% black scrim/white text, original five-second timer and action controls; no registered type, size, settings or native integration changes. Physical-device acceptance pending.

Confirmation fades (2026-11-20, ADR-073): SOS/Calls, Music source handoff, Turn guidance handoff and Google Maps End overlay content/dimming fade over 220 ms, immediate with Reduce motion. Retained outgoing prompts are inert until removed; original deadlines/actions and all widget sizes/settings/types remain unchanged. Native window/app transitions and device accessibility/touch acceptance remain open.
