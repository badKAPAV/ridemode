# Widget catalog

[JSON catalog](../config/widget-catalog.json) proposes stable IDs, dimensions and settings; `WidgetRegistry` implements all 11 active IDs and min/default/max sizes, checked against JSON by `scripts/verify-docs.py` (ADR-001). Dimensions below are columns × rows on a device-wide square grid with at least 12 columns and 6 rows; additional whole columns and rows fill the viewport and odd counts are allowed. Pixel 8a targets about 52 dp square cells; larger screens use at least that side, smaller screens scale down to keep the minimum grid. Overflowed saved widgets are fitted when a valid free placement exists; otherwise their records remain for manual Fit to grid. Catalog width 2147483647 means device-width maximum, clamped to actual columns, for Volume, Calls and Notifications. Other widget maxima stay as listed; height maxima are clamped to available rows. In the editor, Rotate appears only when swapping a widget’s width and height remains valid and an empty placement exists. `WidgetCard` renders every type in editor and Ride; Unimplemented M2/M3 content defaults to explicit Mock/Unavailable states; `WidgetCard` accepts optional typed content for later per-instance adapters. Registry validation rejects unknown IDs and invalid sizes before Room writes. New widgets are placed at their smallest valid registered size when space allows. Settings keys remain proposed and do not yet have per-widget editor controls; the user narrowed actual SOS contact selection/editing to M2 and did not require other per-widget customization for the M1 gate. Normal/OLED visual and accessibility checks remain open.

All widget icons use solid Phosphor `Fill` variants, including Music transport, Clock conditions, Battery charging and Maps; Turn guidance uses a large direction glyph derived from explicit text. Clock uses local time and live or cached weather with an explicit failure state; battery reads local capacity. Separate Weather is no longer addable. Existing Weather placements convert in place to Clock; a page may then have two combined Clock tiles until the user removes one. Shared measured text wraps and scales within the actual rendered bounds, with a 14 sp preferred floor and a smaller emergency fit only when needed. Assistant remains a mock/unavailable card. Calls/Notifications and Turn guidance use current native sources and need device acceptance. Ride and editor preview use the saved widget rectangles even for a page with one visible widget. OLED idle offers the default single-column Classic style and a Row style with larger stacked clock/date at left and centered live song state, live/cached weather and local battery/charging content inside widely spaced 1 dp white-outline black panels at right; the song and weather have white icons. Both keep a wake hint. Music now uses a live session source after the Android access grant; real SOS picker/photo/edit behavior remains M2 work; weather needs device acceptance. Remaining M1 work is user device acceptance of the preview visuals. Current JSON settings keys are proposed only. M1 tests must never interpret mock data as live native integration. See [PRD](PRD.md), [design](DESIGN_SYSTEM.md) and [capabilities](ANDROID_CAPABILITIES.md).

The new `google_maps` widget is isolated from `maps_shortcut` and notification-derived Turn guidance. Other widgets retain their data and saved placements while visually hidden by map expansion. Its live map and route lifecycle still require real-device acceptance; the editor preview is intentionally static.
