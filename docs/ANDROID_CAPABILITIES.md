# Android capability and permission boundaries

Ride, weather, music/notification-listener and private-APK call permissions are declared now; other sensitive grants below remain planned. Grant state may change at any time. Device/Android-version and Play policy behavior requires testing before claims of support.

M2-NAV-001 uses Navigation SDK 6.3.3 (approved ADR-065) and Places SDK 4.3.1. The ignored root `.env` supplies separate Android API keys at build time; release and debug keys must be Android app restricted in GCP, with billing and quota alerts. Navigation SDK supplies the map and route engine; Places Autocomplete (New) is country-restricted to India with session tokens and a minimal selected-place Details call. Precise foreground location is requested at use; idle recenter checks recent cached fixes and makes bounded one-shot fused/network/GPS requests with cancellation, without polling; the SDK also merges `ACCESS_BACKGROUND_LOCATION`, which the app does not request at runtime; approximate-only/denied states show an action instead of a fake position. The point-only confirmation triggers no route request; Start navigation alone calls `setDestination`. The SDK ETA card is hidden, while one Navigator callback supplies custom active ETA, remaining time and distance without polling or another route request. Navigator guidance is stopped, destinations cleared and listeners removed on arrival, explicit end or End Ride. SDK background-location and foreground-service behavior, permission transitions, real route/offline handling and license attribution still need device/release acceptance. Existing Turn guidance and all other widgets remain independent. See [M2-NAV task](../tasks/M2-NAV.md).

The current Ride notification reports only active status and elapsed time, with Open and End Ride actions. It does not track a route or need a foreground service. Closing PiP does not end the Ride session; End Ride removes the notification. The notification can be absent if permission is denied or disabled later.

See [PRD](PRD.md) and [architecture](ARCHITECTURE.md). Android/Play eligibility and device behavior must be checked against current official guidance when implementation begins.

Maps destination selection (2026-11-20): From is fixed to actual Current location. Choose from map reads only the visible map camera target and uses a coordinate Waypoint on explicit Start ride; it adds no geocoding service or permission. Places search/session guards and Start-only Navigation SDK routing remain in force. Native keyboard, attribution, resize/follow and map pin acceptance require a device.

Ongoing navigation (2026-11-20): pinned SDK 6.3.3 exposes setAudioGuidance integer flags, used for Mute / All / Alerts only, with BLUETOOTH_AUDIO on spoken modes; no additional Bluetooth permission or route request is introduced. SDK task removal uses QUIT_SERVICE. Normal navigation end/arrival explicitly stops guidance and clears destinations, disabling navigation UI and restoring idle camera; final SDK cleanup occurs at actual Ride end (ADR-063). Failures are logged and visible. Do not cancel all application notifications: the Ride notification is separate. SDK driving-notification removal still requires device evidence. The reported GPS warning occurred indoors; fresh GPS may be unavailable despite a cached/network position. The app keeps the SDK warning and does not inject fake fixes. [Navigator lifecycle reference](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/Navigator), [audio flags](https://developers.google.com/maps/documentation/navigation/android-sdk/reference/com/google/android/libraries/navigation/Navigator.AudioGuidance), [GPS FAQ](https://developers.google.com/maps/documentation/navigation/android-sdk/faq).

Access links and optional Maps toolbar (2026-11-20): Location/Calls cards use ACTION_APPLICATION_DETAILS_SETTINGS with the current app package; Android exposes Permissions within app details rather than a universally supported public direct permission-list action. Music/messages use notification-listener detail settings on API 30+ (list fallback), and Ride notifications use app notification settings on API 26+ (app-details fallback). Missing/restricted Settings handlers are handled without a crash. No permission is granted automatically. The optional Ride Maps button launches a package-targeted Google Maps URL; if Maps is missing, it tries a browser and otherwise shows an unavailable message. No package-visibility query or new permission is needed. [Android Settings actions](https://developer.android.com/reference/android/provider/Settings).

Speedometer (ADR-057): existing ACCESS_FINE_LOCATION is requested at widget use, with approximate-only treated as insufficient for GPS speed. Permanent denial links to app settings; disabled GPS links to location settings. LocationManager GPS requests run only in resumed Ride with an enabled/visible speedometer configured. GPS subscription stops on pause/end and never records coordinates. Five-second monotonic freshness and reported speed-error filtering prevent stale/fabricated values; indoor reception may be unavailable.

SOS (ADR-058): system ACTION_PICK/Phone.CONTENT_TYPE grants access to a selected phone row; no READ_CONTACTS permission is added. Optional selected photo is copied into a bounded thumbnail; failed photo access uses initials. Contact snapshots are private Room configuration, with existing Android OS backup rules unchanged; no app network sync or address-book scan. Explicit confirmed ACTION_DIAL is default; opt-in ACTION_CALL requests existing CALL_PHONE at use and denial falls back to dialer. Emergency detection falls back safely to dialer. Picker and OEM behavior require real-device verification.

Speedometer includes legacy provider/status callback implementations for the API 24 minimum; native callback contract reference: [Android LocationListener](https://developer.android.com/reference/android/location/LocationListener).

ADR-059 changes call confirmation presentation/timing only: SOS/Recents use large icon-led five-second confirmation controls with progress in Dismiss. A confirmed number is retained separately for CALL_PHONE permission results after removing the dialog; default dialer/direct-call/emergency policy and manifest permissions remain unchanged. Ride/navigation cancellation does not call native stop/end unless explicitly confirmed within its deadline.

Navigation lifecycle/ANR repair (ADR-063): Activity recreation/palette changes retain navigation state independently from native views; PiP/page disposal does not stop guidance. Stop/arrival removes route listeners and explicitly stops guidance/clears destinations; cleanup is only at true Ride end, retaining SDK availability for idle. Forward native view configuration/save/trim. The SDK does not support custom LocationSource, so the previous reset was removed. One active widget owns SDK guidance at a time. Real-device traces show a Google SDK lock inversion; SDK 6.3.3/Kotlin 2.1.21 upgrade was explicitly approved and applied under ADR-065; real-device route stress acceptance remains open. See [ANR evidence](verification/M2_NAV_ANR_2026-11-20.md) and [Google release notes](https://developers.google.com/maps/documentation/navigation/android-sdk/release-notes). No manifest permission changes.

Background End Ride notification now invokes the application SDK owner directly from its Hilt-injected receiver, then ends the Ride session; it does not wait for an offscreen Activity to recompose. Palette generation explicitly observes LocalConfiguration while navigation state remains separately retained. Device component verification is recorded in SESSION_STATE; live-guidance notification removal remains an acceptance check.

Assistant widget (ADR-066): explicit live tap calls public Activity.showAssist (API 23+, app min 24) on the current foreground Activity, unwrapping theme contexts. Android invokes the user's current assistant; false/failed requests show unavailable feedback. Ridemode requests no microphone/assistant role/package visibility permission and attaches no custom route/notification payload. Normal platform assist context, assistant permissions and any provider network behavior are governed by Android/user/provider. Editor never launches. [Activity.showAssist reference](https://developer.android.com/reference/android/app/Activity#showAssist(android.os.Bundle)).

Turn guidance retains its existing user-granted notification listener and two-minute expiry. All absent/stale/no-access states show the idle prompt; grant access through Access and Privacy. A confirmed tap explicitly launches Google Maps; missing/restricted app shows feedback, with no browser fallback on this widget. It neither starts an in-app SDK route nor changes other widget sources. The disabled Ride rail button invokes no mock/voice action.

Music source UI handoff (ADR-067): MediaController.sessionActivity supplies the provider's PendingIntent; it stays in memory and is sent only after explicit timed confirmation. Android 34+ uses ActivityOptions sender opt-in; Android 36 selects MODE_BACKGROUND_ACTIVITY_START_ALLOW_IF_VISIBLE. If missing/cancelled, try only the tapped source package launcher; Android package visibility or absent UI can prevent fallback, with unavailable feedback. No broad package queries, new permission, playback command or foreground service. Device/provider validation pending. [Platform sender requirements](https://developer.android.com/guide/components/activities/secure-bal).
