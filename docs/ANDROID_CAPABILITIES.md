# Android capability and permission boundaries

Ride, weather, music/notification-listener and private-APK call permissions are declared now; other sensitive grants below remain planned. Grant state may change at any time. Device/Android-version and Play policy behavior requires testing before claims of support.

| Capability | Grant/use | Restriction and fallback | Milestone |
|---|---|---|---|
| Picture-in-picture | System PiP for the active Ride Activity on API 26+; no separate permission | Compact status view on Home/Recents; unsupported devices use normal activity behavior. Pixel 8a Home entry and close passed. | M1 |
| POST_NOTIFICATIONS | Runtime request when starting Ride on API 33+ | Denial allows Ride but prevents its ongoing shade controls and Live Update; user sees a brief explanation. User manually verified the denial path on 2026-11-18. No access to other apps' notifications. | M1 |
| POST_PROMOTED_NOTIFICATIONS | Nonruntime permission and promotion request for the ongoing Ride notification on supported Android | Android decides promotion eligibility and presentation; ordinary ongoing notification remains the fallback. Pixel 8a system marked this notification promoted. | M1 |
| NotificationListenerService | Existing service; explicit user special-access grant via Settings, checked on activity resume and listener lifecycle | The listener reads active media sessions, current message/high-priority content and ongoing Google Maps notification extras. Turn guidance is in memory only, accepts recognizable maneuvers, expires after two minutes and clears on removal/revocation; Maps may omit or change fields. Device behavior not verified. | M2 music, notification feed and Turn guidance IN_PROGRESS |
| MediaSessionManager / MediaController | Active sessions via listener authorization; playing session preferred | Shows available metadata/artwork/progress; controls only advertised actions; clears disappearing sessions. No private library access. Device app compatibility not yet verified. | M2 music IN_PROGRESS |
| AudioManager | `STREAM_MUSIC` read/write within reported minimum/maximum; Settings content observer and audio-device callback refresh, plus Activity resume refresh; no permission | Android owns the active output route; zero adjustable range or rejected write shows unavailable/actual level. | Contacts | System picker where sufficient; READ_CONTACTS only at selection if needed | Denial yields manual/dial fallback; local references only. | M2 |
| ACTION_DIAL / CALL_PHONE | Dial needs no direct-call grant; Calls widget ACTION_CALL requests runtime CALL_PHONE and confirmation; emergency numbers open the dialer | Emergency numbers through system dialer; OS owns incoming calls. | M2 |

M2-NAV-001 adds Navigation SDK 6.1.0 and Places SDK 4.3.1. The ignored root `.env` supplies separate Android API keys at build time; release and debug keys must be Android app restricted in GCP, with billing and quota alerts. Navigation SDK supplies the map and route engine; Places Autocomplete (New) is country-restricted to India with session tokens and a minimal selected-place Details call. Precise foreground location is requested at use; idle recenter checks recent cached fixes and makes bounded one-shot fused/network/GPS requests with cancellation, without polling; the SDK also merges `ACCESS_BACKGROUND_LOCATION`, which the app does not request at runtime; approximate-only/denied states show an action instead of a fake position. The point-only confirmation triggers no route request; Start navigation alone calls `setDestination`. The SDK ETA card is hidden, while one Navigator callback supplies custom active ETA, remaining time and distance without polling or another route request. Navigator guidance is stopped, destinations cleared and listeners removed on arrival, explicit end or End Ride. SDK background-location and foreground-service behavior, permission transitions, real route/offline handling and license attribution still need device/release acceptance. Existing Turn guidance and all other widgets remain independent. See [M2-NAV task](../tasks/M2-NAV.md).

The current Ride notification reports only active status and elapsed time, with Open and End Ride actions. It does not track a route or need a foreground service. Closing PiP does not end the Ride session; End Ride removes the notification. The notification can be absent if permission is denied or disabled later.

See [PRD](PRD.md) and [architecture](ARCHITECTURE.md). Android/Play eligibility and device behavior must be checked against current official guidance when implementation begins.
