# Navigation lifecycle / ANR evidence — 2026-11-20

Read-only diagnostics from the connected Pixel 8a running Android 17. No route was started, wallpaper changed, app data cleared or APK installed during evidence collection. Only Ridemode findings are recorded here; raw diagnostic files remain under /tmp.

## Observed ANRs

Android ApplicationExitInfo records two Ridemode RideActivity ANRs at 12:03 and 12:12 IST, each with `Waited 5003ms for MotionEvent`. No Ridemode Java fatal-exception stack remained in the crash buffer.

Both Android Dropbox traces show the same SDK-internal lock inversion:

```text
main thread: SystemSensorManager sensor callback
  Navigation SDK internal de.t.onAccuracyChanged
  holds sensor lock A
  waits for internal de.m lock B

NavInternal thread:
  Navigation SDK internal de.m.f
  holds lock B
  waits in internal de.v for sensor lock A
```

This is an actual deadlock in SDK code, rather than evidence of a Compose touch exception. It explains the frozen input and eventual OS termination. It does not establish exactly which application action initiated the SDK transition. The baseline project at capture was pinned to Navigation SDK 6.1.0; the approved update is now 6.3.3.

## App-side findings and fixes

- RideActivity.onDestroy always called finishMapSessions; a configuration recreation therefore stopped guidance. A retained navigation ViewModel now separates route state from the replaceable Activity/native views, using app context and weak Activity binding.
- Stop previously called Navigator.cleanup while retaining the same map for idle and restored/recentered idle from repeated native UI callbacks. Stop now removes route listeners, calls stopGuidance/clearDestinations, restores idle once and defers cleanup to true Ride end. Unsupported custom LocationSource reset removed.
- Stale map/SDK callbacks are checked against current view/route/ride identity. Singleton route leases prevent a different widget or late callback from stopping a newer route. Invalid map handles trigger one rebuild then manual recovery rather than a loop.
